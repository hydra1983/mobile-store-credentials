iOS

App Store

确认正式发布目标

Bundle ID、Apple Developer Team、应用能力。

Skill 覆盖

◇构建签名

  1. 01

    .p12 分发签名文件

    来源
    Apple 签发分发证书，团队用证书和私钥导出 .p12。
    保管／授权
    团队保管，授权构建环境使用。
    Skill 协助
    核对私钥、证书、Team 和有效期。吊销查 Apple 后台。
    命令与操作入口
    • 授权 CLI签发分发证书

      Apple Account Holder 或 Admin 操作。已有签名身份可先复用。

      fastlane cert --generate_apple_certs --team_id "$TEAM_ID"
    • 后台入口后台签发，本机导出

      Apple Developer → Certificates, Identifiers & Profiles → Certificates → Apple Distribution。Xcode → Settings → Accounts → Manage Certificates → Export Certificate。导出机器须有对应私钥。

    • 本地检查检查 .p12 和描述文件

      按终端提示输入密码。

      python3 scripts/check-ios-signing.py \
  --bundle-id "$BUNDLE_ID" --team-id "$TEAM_ID" \
  --p12 "$P12_PATH" --profile "$PROFILE_PATH"
  2. 02

    .p12 密码与项目变量

    来源
    导出人设密码，项目脚本定变量名。
    保管／授权
    团队保管密码，按需注入构建环境。
    Skill 协助
    找出变量，验证密码能否打开 .p12。
    命令与操作入口
    • 团队配置设置或取用密码

      新密码在 Xcode 导出时设置。已有密码从团队密钥库取得。

    • 本地检查CI 读取密码

      给 .p12 检查命令加上以下参数，密码由 CI 注入。

      --password-env P12_PASSWORD
  3. 03

    .mobileprovision 描述文件

    来源
    Apple 按 App ID 和分发证书签发。
    保管／授权
    账号持有人或管理员下载，团队保管。
    Skill 协助
    指导获取，核对 App ID、Team、类型、有效期、权限与证书。
    命令与操作入口
    • 授权 CLI下载或创建

      --readonly 只下载已有文件。获准创建时去掉它。CERT_ID 用 Apple 证书资源 ID，OUTPUT_DIR 用新目录。

      fastlane sigh --app_identifier "$BUNDLE_ID" \
  --team_id "$TEAM_ID" --cert_id "$CERT_ID" \
  --output_path "$OUTPUT_DIR" --skip_install --readonly
    • 后台入口手动创建并下载

      Account Holder 或 Admin：Apple Developer → Certificates, Identifiers & Profiles → Profiles → + → App Store Connect → 选 App ID 和证书 → Generate → Download。

    • 本地检查核对描述文件

      运行 .p12 卡的检查命令，--profile 指向下载的文件。

↑商店上传凭据

  1. 01

    .p8 上传私钥

    来源
    App Store Connect 生成 Team Key，私钥限下载一次。
    保管／授权
    管理员选角色，团队保管私钥。
    Skill 协助
    定位 .p8，判断能否复用，缺件时给获取步骤。
    命令与操作入口
    • 管理员后台创建 Team Key

      App Store Connect → Users and Access → Integrations → App Store Connect API → Team Keys → Generate API Key → 选角色 → Download API Key。首次 API 访问由 Account Holder 在 Integrations 申请。

    • 本地检查检查私钥格式

      启用状态和上传角色在 Team Keys 核对。

      openssl pkey -in "$ASC_P8_PATH" -check -noout
  2. 02

    Key ID

    来源
    App Store Connect 为每把密钥分配。
    保管／授权
    团队把 ID 和对应 .p8 配在一起。
    Skill 协助
    对照项目配置和后台密钥记录。
    命令与操作入口
    • 后台入口复制 Key ID

      在 .p8 卡的 Team Keys 页面，从对应密钥行复制。

  3. 03

    Issuer ID

    来源
    App Store Connect 提供团队的 Issuer ID。
    保管／授权
    团队配置 Issuer ID，管理员确认团队和角色。
    Skill 协助
    核对目标团队，标记待核实的上传权限。
    命令与操作入口
    • 后台入口复制 Issuer ID

      在 .p8 卡的 Team Keys 页面上方复制。

确认正式发布目标

正式包名、Play 应用、发布配置。

Skill 覆盖

◇构建签名

  1. 01

    上传 keystore（如 .jks）

    来源
    团队在本地生成。已上架应用沿用登记的上传密钥。
    保管／授权
    团队保管。丢失时由有权限的 Play 人员申请重置。
    Skill 协助
    定位文件、判断能否复用，给出首发或重置步骤。
    命令与操作入口
    • 本地创建生成 JKS

      首发使用新文件路径，按提示设置密码。

      keytool -genkeypair -keystore "$NEW_UPLOAD_KEYSTORE" \
  -alias "$UPLOAD_KEY_ALIAS" -keyalg RSA -keysize 2048 \
  -validity 10000 -storetype JKS
    • 管理员后台申请重置上传密钥

      Play Console → 目标应用 → Test and release → App integrity → Play app signing → Request upload key reset。提交新公开证书。

  2. 02

    alias 与签名密码

    来源
    团队创建密钥时设置 alias 和两类密码。
    保管／授权
    alias 放项目配置，密码放本机或 CI 密钥库。
    Skill 协助
    用 keytool 确认 alias 含私钥。签名与私钥密码另验。
    命令与操作入口
    • 本地检查查看 alias 和指纹

      按终端提示输入 keystore 密码。

      keytool -list -v -keystore "$UPLOAD_KEYSTORE" \
  -alias "$UPLOAD_KEY_ALIAS"
  3. 03

    上传证书与 SHA-256

    来源
    证书来自上传密钥，Play Console 显示已登记的指纹。
    保管／授权
    有权限的 Play 人员登记，团队可保存公开指纹。
    Skill 协助
    比对上传证书的 SHA-256，注明基准来源。
    命令与操作入口
    • 本地检查导出公开证书

      SHA-256 用上一卡的 keytool -list -v 查看。登记或重置时导出公开证书。

      keytool -exportcert -rfc -keystore "$UPLOAD_KEYSTORE" \
  -alias "$UPLOAD_KEY_ALIAS" -file "$UPLOAD_CERT_PEM"
    • 后台入口查看登记指纹

      Play Console → 目标应用 → Test and release → App integrity → Play app signing → Upload key certificate → SHA-256。

↑商店上传凭据

  1. 01

    Android Publisher API 与服务账号

    来源
    Google Cloud 提供 API，Cloud IAM 创建账号。
    保管／授权
    有权限的 Cloud 项目人员启用 API、管理账号。
    Skill 协助
    默认离线预览。显式 --apply 后检查云端并按需补齐。
    命令与操作入口
    • 脚本可执行预览或执行准备脚本

      具备 Cloud 项目权限后，将 --dry-run 换成 --apply。也会按需准备 JSON。

      bash scripts/prepare-google-play-credentials.sh \
  --project "$PROJECT_ID" --service-account "$ACCOUNT_ID" \
  --key-path "$PLAY_JSON" --dry-run
    • 后台入口启用 API 或管理账号

      Google Cloud Console → APIs & Services → Library → Google Play Android Developer API → Enable。账号在 IAM & Admin → Service Accounts。

  2. 02

    发布服务账号 JSON

    来源
    Google Cloud IAM 生成 JSON 密钥。
    保管／授权
    有权限的 Cloud 人员创建，团队保管私钥。
    Skill 协助
    检查 JSON 类型、账号和配置，按需生成新文件。
    命令与操作入口
    • 授权 CLI为已有账号生成 JSON

      优先用上一卡的脚本检查现有文件。新密钥保存到私有目录中的新文件。

      gcloud iam service-accounts keys create "$NEW_PLAY_JSON" \
  --iam-account="$SERVICE_ACCOUNT_EMAIL" --project="$PROJECT_ID" \
  --key-file-type=json
    • 后台入口创建并下载 JSON

      Google Cloud Console → IAM & Admin → Service Accounts → 选账号 → Keys → Add key → Create new key → JSON。

  3. 03

    目标应用的发布权限

    来源
    Play Console 按服务账号邮箱记录应用权限。
    保管／授权
    Play 管理员为目标应用授予所需权限。
    Skill 协助
    指导核对上传权限。可用 gpd 探测包级访问。
    命令与操作入口
    • 管理员后台授权目标应用

      Play Console → Users and permissions → 邀请或选择服务账号 → App permissions → 选应用和所需权限。已有管理授权的集成可用 users.create 和 grants.create。

    • 授权 CLI探测包级访问

      会创建并尝试删除临时 edit。上传权限单独核实。

      gpd auth check --key-path "$PLAY_JSON" \
  --package "$ANDROID_PACKAGE" --store-tokens never --output json
