Skill coverage

◇Build signing

  1. 01

    .p12 distribution identity

    Source
    Apple issues the certificate. The team exports it with its private key as a .p12.
    Custody / access
    The team stores it and grants the build environment access.
    Skill support
    Checks the key, certificate, team, and expiry. Check revocation in the Apple portal.
    Commands and console paths
    • Authorized CLIIssue a distribution certificate

      An Apple Account Holder or Admin can run this. Reuse an existing identity when possible.

      fastlane cert --generate_apple_certs --team_id "$TEAM_ID"
    • Console pathIssue in the portal, export locally

      Apple Developer → Certificates, Identifiers & Profiles → Certificates → Apple Distribution. Xcode → Settings → Accounts → Manage Certificates → Export Certificate. Export from the Mac holding the private key.

    • Local checkCheck the .p12 and profile

      Enter the password at the terminal prompt.

      python3 scripts/check-ios-signing.py \
  --bundle-id "$BUNDLE_ID" --team-id "$TEAM_ID" \
  --p12 "$P12_PATH" --profile "$PROFILE_PATH"
  2. 02

    .p12 password and project variable

    Source
    The person exporting the file sets the password. The project script names the variable.
    Custody / access
    The team stores the password and supplies it to the build environment as needed.
    Skill support
    Finds the variable and checks whether the password opens the .p12.
    Commands and console paths
    • Team setupSet or retrieve the password

      Set a new password during Xcode export. Retrieve an existing one from the team's secret store.

    • Local checkRead the password in CI

      Add this option to the .p12 checker. Supply the password through CI.

      --password-env P12_PASSWORD
  3. 03

    .mobileprovision profile

    Source
    Apple issues it for an App ID and distribution certificate.
    Custody / access
    An Account Holder or Admin downloads it. The team stores it.
    Skill support
    Guides retrieval and checks App ID, team, profile type, expiry, entitlements, and certificate.
    Commands and console paths
    • Authorized CLIDownload or create

      --readonly downloads an existing profile. Remove it when authorized to create one. Use the Apple certificate resource ID for CERT_ID and a new directory for OUTPUT_DIR.

      fastlane sigh --app_identifier "$BUNDLE_ID" \
  --team_id "$TEAM_ID" --cert_id "$CERT_ID" \
  --output_path "$OUTPUT_DIR" --skip_install --readonly
    • Console pathCreate and download in the portal

      Account Holder or Admin → Apple Developer → Certificates, Identifiers & Profiles → Profiles → + → App Store Connect → select App ID and certificate → Generate → Download.

    • Local checkCheck the profile

      Run the checker from the .p12 card with --profile pointing to the downloaded file.

↑Upload credentials

  1. 01

    .p8 upload private key

    Source
    App Store Connect generates the Team Key. The private key can be downloaded once.
    Custody / access
    An admin selects the role. The team stores the private key.
    Skill support
    Finds the .p8, checks reuse, and gives retrieval steps if it is missing.
    Commands and console paths
    • Admin consoleCreate a Team Key

      App Store Connect → Users and Access → Integrations → App Store Connect API → Team Keys → Generate API Key → select a role → Download API Key. The Account Holder requests initial API access under Integrations.

    • Local checkCheck the private key format

      Confirm key status and upload role under Team Keys.

      openssl pkey -in "$ASC_P8_PATH" -check -noout
  2. 02

    Key ID

    Source
    App Store Connect assigns one to each key.
    Custody / access
    The team configures the ID with the matching .p8.
    Skill support
    Compares the project configuration with the console record.
    Commands and console paths
    • Console pathCopy the Key ID

      Open Team Keys using the path in the .p8 card. Copy the ID from the matching key row.

  3. 03

    Issuer ID

    Source
    App Store Connect provides the team's Issuer ID.
    Custody / access
    The team configures the Issuer ID. An admin confirms the team and role.
    Skill support
    Checks the target team and flags upload permissions still to verify.
    Commands and console paths
    • Console pathCopy the Issuer ID

      Copy it from the top of the Team Keys page described in the .p8 card.

Confirm the production target

Production package name, Play app, and release configuration.

Skill coverage

◇Build signing

  1. 01

    Upload keystore (such as .jks)

    Source
    The team generates it locally. Published apps keep using the registered upload key.
    Custody / access
    The team stores it. If lost, an authorized Play user requests a reset.
    Skill support
    Finds the keystore, checks reuse, and gives first-release or reset steps.
    Commands and console paths
    • Local creationGenerate a JKS

      For a first release, use a new file path and set the password at the prompt.

      keytool -genkeypair -keystore "$NEW_UPLOAD_KEYSTORE" \
  -alias "$UPLOAD_KEY_ALIAS" -keyalg RSA -keysize 2048 \
  -validity 10000 -storetype JKS
    • Admin consoleRequest an upload key reset

      Play Console → select the app → Test and release → App integrity → Play app signing → Request upload key reset. Submit the new public certificate.

  2. 02

    Alias and signing passwords

    Source
    The team sets the alias and both passwords when creating the key.
    Custody / access
    Keep the alias in project configuration and passwords in a local or CI secret store.
    Skill support
    Uses keytool to check that the alias has a private key. Signing and the key password need separate checks.
    Commands and console paths
    • Local checkView the alias and fingerprint

      Enter the keystore password at the terminal prompt.

      keytool -list -v -keystore "$UPLOAD_KEYSTORE" \
  -alias "$UPLOAD_KEY_ALIAS"
  3. 03

    Upload certificate and SHA-256

    Source
    The upload key provides the certificate. Play Console shows the registered fingerprint.
    Custody / access
    An authorized Play user registers it. The team can keep the public fingerprint.
    Skill support
    Compares the upload certificate SHA-256 and records where the reference came from.
    Commands and console paths
    • Local checkExport the public certificate

      Use keytool -list -v from the previous card to view SHA-256. Export the public certificate for registration or a reset.

      keytool -exportcert -rfc -keystore "$UPLOAD_KEYSTORE" \
  -alias "$UPLOAD_KEY_ALIAS" -file "$UPLOAD_CERT_PEM"
    • Console pathView the registered fingerprint

      Play Console → select the app → Test and release → App integrity → Play app signing → Upload key certificate → SHA-256.

↑Upload credentials

  1. 01

    Android Publisher API and service account

    Source
    Google Cloud provides the API. Cloud IAM creates the account.
    Custody / access
    Authorized Cloud project users enable the API and manage the account.
    Skill support
    Previews offline by default. Pass --apply to check Cloud and provision what is missing.
    Commands and console paths
    • ScriptPreview or run setup

      With Cloud project permissions, replace --dry-run with --apply. The script also prepares the JSON if needed.

      bash scripts/prepare-google-play-credentials.sh \
  --project "$PROJECT_ID" --service-account "$ACCOUNT_ID" \
  --key-path "$PLAY_JSON" --dry-run
    • Console pathEnable the API or manage the account

      Google Cloud Console → APIs & Services → Library → Google Play Android Developer API → Enable. Find accounts under IAM & Admin → Service Accounts.

  2. 02

    Publisher service account JSON

    Source
    Google Cloud IAM generates the JSON key.
    Custody / access
    An authorized Cloud user creates it. The team stores the private key.
    Skill support
    Checks the JSON type, account, and configuration. Generates a new file when needed.
    Commands and console paths
    • Authorized CLIGenerate JSON for an existing account

      Check for an existing file with the script in the previous card. Save a new key to a new file in a private directory.

      gcloud iam service-accounts keys create "$NEW_PLAY_JSON" \
  --iam-account="$SERVICE_ACCOUNT_EMAIL" --project="$PROJECT_ID" \
  --key-file-type=json
    • Console pathCreate and download JSON

      Google Cloud Console → IAM & Admin → Service Accounts → select the account → Keys → Add key → Create new key → JSON.

  3. 03

    App release permissions

    Source
    Play Console records app permissions against the service account email.
    Custody / access
    A Play admin grants the required permissions for the target app.
    Skill support
    Guides upload permission checks. gpd can probe package access.
    Commands and console paths
    • Admin consoleGrant access to the target app

      Play Console → Users and permissions → invite or select the service account → App permissions → select the app and permissions. Authorized management integrations can use users.create and grants.create.

    • Authorized CLIProbe package access

      Creates a temporary edit and attempts to delete it. Verify upload permissions separately.

      gpd auth check --key-path "$PLAY_JSON" \
  --package "$ANDROID_PACKAGE" --store-tokens never --output json
